# 技术类

适用：AI 工具和模型、软件产品、技术方案和架构、开发经验、硬件和数码产品发布、技术教程。

## 听完要带走

1. 它解决什么问题（一个具体场景）。
2. 核心做法是什么（一句话 + 一个类比）。
3. 和以前的做法比，好在哪。
4. 代价和门槛：要花多少钱、要什么条件、哪里会出问题。
5. 跟我有什么关系：谁该关心，想试的话从哪一步开始。

## 精讲稿里要标【】的

- 问题场景里最有画面感的那个细节。
- 核心机制的 1～3 个关键部件或步骤（用对谈里会说的名字）。
- 关键数字：性能、成本、规模、时间、数量。写清是谁报的（作者自测、厂商宣传、第三方评测）。
- 拿来比较的对象（"以前用聊天窗口""比上一代"）。
- 门槛和代价里最实在的那个（价格、硬件、技能）。
- 产品名和版本号：念法定下来，标一次。

## 怎么讲给外行

- **先场景，后方案**：从"你有没有遇到过……"开始，不从"这个系统由三部分组成"开始。
- **按"它干什么"来定义**："中台就是所有消息先到的一个收发室"，不说"中台是一种架构模式"。
- **类比用日常的**：收发室、餐厅后厨、快递分拣、公司前台、审批签字。一个概念一个类比，不叠两个。类比和实际不一样的地方，只有会让人误解时才说。
- **架构讲成一件事的经过**："一个告警进来，先到中台，中台查规则，交给某个 Agent，做完了在飞书上找你签字。"不超过 4 步。
- **英文和缩写**：第一次说"中文意思，英文叫 XX"，之后固定一种说法。能不用缩写就不用；CI、API、PR 这类，说一次就换成"自动检查上线那一套""接口""一次代码提交"。
- **代码、命令、配置文件不念**，只说它起什么作用。
- **数字给尺度**："两周 298 个，差不多每天二十个。"

## 对谈怎么展开

- 开场：用一个痛点场景切入，一两句说清这篇文章给的办法。
- 正文每段：问题 → 做法（类比） → 效果（数字）。
- 主持人替外行问："这跟我有什么关系？""那它要是做错了呢？""我不会写代码能用吗？"
- 讨论段可以聊：代价和局限、适合谁不适合谁、是不是作者的个人条件太特殊、会不会很快过时。
- 自测问"为什么这样设计"，不问名词。例："为什么作者不让 Agent 自己上线代码？"

## 容易出错

- 把厂商宣传、作者自报的数字说成事实。要说"作者说""官方说"。
- 把演示、预告、内测中的功能说成已经能用。
- 价格、版本、排名会变，说"写文章的时候"。
- 讲得太细：一期里新概念不超过 5 个，其余的一句带过或不讲。

## 示例片段（自己写的）

```
女：我先说个场景啊。你早上醒来，手机上有一条告警，说网站挂了……
男：然后你得爬起来，开电脑，找 Agent，跟它说"帮我查一下"。
女：对，它才开始干活。
男：作者觉得问题就在这儿——人一不在，什么都不会发生。人成了起点，也就成了瓶颈。
女：所以他的办法是，让告警自己去叫 Agent？
男：对。所有这类消息先到一个地方，他叫"中台"，你就当它是公司的收发室。
```
