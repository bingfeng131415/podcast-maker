# 讲给谁听：默认听众、用户指定的角度

## 默认听众：聪明的外行

用户没说听众是谁时，按这个人来写：

- 好奇、愿意学，但**不是这个领域的人**，没读过原文。
- 在开车、走路，**只能听**，看不到字和图，会走神。
- 听得懂日常的话，听不懂行话和缩写，也不会停下来查。

所以：

- **内容可以深，话要浅。** 核心观点、关键数字一个都不少，但每一个都用大白话说出来。
- **专业词三步走**：先说它是干什么的 → 再说它叫什么 → 之后固定这一个叫法。不需要名字也能讲清的，就不出现名字。
- **行话换成人话**：赋能、抓手、闭环、颗粒度、底层逻辑、范式、链路、对齐、心智……这类词不用，说它具体指什么。
- **一期新概念不超过 5 个**，其余的一句带过。
- **关键数字说准，再给个感觉**："298 个，差不多每天二十个。""百分之二十五，就是一百块的东西多收二十五块。"不重要的数字说大概或者不说。
- **听众记得住的才算讲到**：关键概念和结论，后面再自然地提一两次。

## 用户指定了听众、侧重或讲法

用户可能会说："讲给我爸妈听""侧重对普通人的影响""从产品经理的角度""多讲点怎么用""用讲故事的方式"。**这一期按这个来，优先于默认规则和材料类型说明。**

### 先写下来

在精讲稿的开头写一行：

```
> 这一期的要求：听众 ……；侧重 ……；讲法 ……
```

没说的项不写。精讲稿的"核心要点"和"值得聊的地方"也要按这个要求挑。

### 怎么落到稿子里

| 要落实的 | 做法 |
|---|---|
| 内容分配 | 侧重的那部分占正文一半以上。其他内容压成背景，一两句交代。标了【】的关键信息仍然要讲到，可以简讲。 |
| 开场 | 第一分钟就点明这一期的角度："今天我们专门从……的角度聊。" |
| 主持人 | 代表这类听众，问他们真会问的问题，用他们的词。 |
| 例子 | 从这类人的生活和工作里找。 |
| 用词和深浅 | 按这类人的水平调。用户说听众是业内人士时，可以保留术语、讲细节，默认外行的规则放宽。 |
| 讨论段 | 围绕这个角度展开：对这类人有什么用、要注意什么。 |
| 自测 | 问这个角度上的问题。 |
| 原文没有的 | 原文没有这个角度的信息时，直说"文章没讲到这一点"，可以说自己的推测（标明是推测），不编。 |

### 常见的几种

| 用户说 | 怎么写 |
|---|---|
| 讲给孩子、中学生听 | 例子来自学校和家里；不出现英文缩写；每段最多一个新概念；主持人扮演好奇的学生，多问"为什么"；时长更短。 |
| 讲给爸妈、老人听 | 多讲对生活的影响和"要怎么办"；例子用买菜、看病、养老金、手机；句子更短；不用网络用语；涉及钱和手机操作的，提醒防骗。 |
| 讲给老板、管理者听 | 结论先说；讲投入、产出、风险、要不要做；机制少讲。 |
| 讲给业内人、程序员听 | 保留术语，讲实现细节、取舍和坑；可以质疑方法。 |
| 侧重对普通人的影响 | 讲"如果你是……"的场景，至少两类人；讲具体要做什么。 |
| 侧重怎么用、怎么上手 | 讲清第一步做什么、要准备什么、最容易卡在哪；原文没写步骤的，说"文章没给具体步骤"。 |
| 侧重争议、批判地看 | 讨论段变长，两人各持一方；作者的论证先讲到最有说服力的样子，再挑毛病。 |
| 用讲故事的方式 | 从一个人物或场面开始，按时间往下讲；概念放进故事里讲。事实和细节不编，想象的部分说"咱们想象一下"。 |
| 简单点、短一点 | 只留最核心的 2～3 个要点，【】标的信息也只留最关键的。 |

### 写完对一遍

- 开场有没有点明角度？
- 侧重的部分是不是占了一半以上？
- 主持人的问题像不像这类听众会问的？
- 有没有一个例子是这类人熟悉的？
